# QA 통합 툴

**게임 QA에 필요한 데이터 비교, 아이템 코드 변환과 드랍 테이블 검수를 하나의 웹사이트에서 처리하는 도구입니다.**

**버전 1.4.9** · **개발자 zeloso97/김용학**

로컬 PC에서 실행하거나 내부 IP로 사내 직원들과 공유할 수 있습니다. JSON 비교와 아이템 변환은 브라우저에서 처리하고, 드랍 조회·비교는 담당자가 등록한 공통 데이터를 사용합니다.

[변경 이력](CHANGELOG.md) · [JSON 비교 가이드](JSON_COMPARE_GUIDE.md) · [드랍 검수 가이드](DROP_GUIDE.md) · [드랍 변경 비교 가이드](DROP_COMPARE_GUIDE.md)

## 주요 기능

| 기능 | 입력 | 제공 결과 |
| --- | --- | --- |
| JSON 폴더 비교 | 구버전·신버전 최상위 폴더 2개 | 변경·추가·삭제 파일, 변경 값과 원본 행 번호 |
| 아이템 코드 변환 | 엑셀 파일 또는 복사한 셀 데이터 | 9자리 아이템 코드·강화도 TSV, 데이터를 적용한 Python 매크로 |
| 드랍 테이블 검수 | 담당자가 등록한 Drop·NPC·Item·String | 몬스터 이름·ID 검색, 아이템명·수량·최종 확률 |
| 드랍 변경 비교 | 이전·변경 Drop 파일 2개 | 변경 몬스터 목록, 카테고리별 요약, 몬스터별 상세 변경 |

- 메뉴를 이동해도 입력과 결과를 유지합니다.
- 기본 테마는 **화이트**이며, 상단 고정 바에서 **화이트 / 다크**를 선택할 수 있습니다.
- 선택한 테마는 브라우저에 저장됩니다. 테마 전환 시 입력과 결과를 유지합니다.
- 확률 상승은 옅은 빨강, 하락은 옅은 파랑으로 표시합니다.

## 빠른 시작

### 실행 환경

- **서버 PC:** Node.js 18 이상. 프로젝트에 포함된 Node 서버를 사용합니다.
- **사용자 PC:** 폴더 선택과 XLSX 읽기에 필요한 기능을 지원하는 Chrome 또는 Edge.
- **매크로 실행 PC:** Windows, Python 3.9 이상과 별도 입력 제어 패키지. 웹 도구만 사용하면 Python은 필요하지 않습니다.

웹 도구에 필요한 외부 코드는 프로젝트에 동봉되어 있습니다. 현재 구성은 별도 `npm install`이나 빌드 없이 실행할 수 있습니다.

### 로컬 실행

저장소를 내려받고, **`package.json`과 `server.mjs`가 있는 프로젝트 최상위 폴더**에서 실행합니다.

```powershell
node server.mjs --port 5175
```

브라우저에서 [http://localhost:5175/](http://localhost:5175/)에 접속합니다.

`npm run dev` 또는 Windows의 `start.bat`으로도 실행할 수 있습니다. 기본 포트는 **5175**입니다.

### 사내 공유

서버를 실행할 PC에서 다음 명령을 사용합니다.

```powershell
node server.mjs --host 0.0.0.0 --port 5175
```

`npm run share` 또는 Windows의 `share-lan.bat`으로도 실행할 수 있습니다.
직원에게 터미널의 **Network 주소**를 공유합니다. 접속 주소는 `http://서버PC의내부IP:5175/` 형태이며, 직원 PC에서 `localhost`를 입력하면 해당 직원 자신의 PC를 가리킵니다.

서버 PC와 Node 프로세스가 켜져 있어야 하며, 사내 네트워크에서 해당 포트에 접근할 수 있어야 합니다.

### 종료와 재실행

- 종료하려면 서버 터미널에서 **Ctrl+C**를 누릅니다.
- 실행 중인 터미널을 유지하세요. Windows 부팅 시 자동 실행이나 서비스 등록 기능은 포함되어 있지 않습니다.
- `Port 5175 is already in use`가 나오면 해당 포트를 사용하는 프로그램을 확인합니다. 기존 QA 서버가 실행 중이라면 그 터미널에서 종료한 후 다시 실행합니다.
- 파일 교체 후 화면에 반영되지 않으면 **Ctrl+F5**로 새로고침합니다. 서버 코드를 교체한 경우에는 Node 서버도 재시작합니다.

## 기능별 사용법

### 1. JSON 폴더 비교

1. **JSON 폴더 비교** 메뉴를 엽니다.
2. 구버전과 신버전의 최상위 폴더를 각각 선택합니다.
3. 비교를 실행하고 변경된 파일을 선택해 상세 내용을 확인합니다.

하위 폴더를 포함한 **상대 경로**로 파일을 연결합니다. `.json`을 비교하며 `.meta`, `.bytes`는 제외합니다.

- 들여쓰기·개행·객체 키 순서는 무시하고 실제 JSON 구조와 값을 비교합니다.
- 문자열 내부 공백과 값의 자료형은 구분하며, 큰 숫자의 정밀도를 유지합니다.
- 배열은 식별자 기반 비교와 사용자 지정 키를 지원합니다.
- 변경·추가·삭제·오류 파일을 구분하고, 상세 화면에 이전·변경 값과 원본 행 번호를 표시합니다.
- 진행률, 취소와 페이지 나누기를 지원합니다.

자세한 비교 기준과 배열 처리 방식은 [JSON_COMPARE_GUIDE.md](JSON_COMPARE_GUIDE.md)를 참고하세요.

### 2. 아이템 코드 변환

엑셀에서 복사한 셀을 붙여넣거나 **XLSX / CSV / TSV / TXT** 파일을 선택합니다.

- **장비 코드 4자리 + 접두·이름 코드 5자리**로 9자리 코드를 생성합니다.
- 각 행을 왼쪽에서 오른쪽으로 처리한 뒤 다음 행으로 이동하며, 중복 항목을 유지합니다.
- 강화도는 별도 셀 또는 이름 뒤 숫자에서 읽습니다. 없으면 0으로 처리합니다.
- 등록된 보정 규칙을 적용하고, 확정할 수 없는 명칭은 오류로 표시합니다.
- 결과는 **아이템 코드 / 강화도**의 머리글 없는 2열 TSV로 복사하거나 저장합니다.

예: `일리아나 권갑 +9` → `110160106` / `9`

### 입력 방법

- **셀 붙여넣기**: 엑셀에서 데이터 범위를 복사해 입력창에 붙여넣습니다.
- **엑셀 파일**: .xlsx 파일을 선택하고 처리할 시트를 고릅니다.
- UTF-8 .csv(쉼표 구분), .tsv, .txt(탭 구분)도 읽습니다.
- .xls/.xlsm 또는 암호화된 파일은 .xlsx로 저장하거나 셀을 복사해 붙여넣으세요.
- **제공 예시 불러오기**로 사용자 표 56행 전체를 확인할 수 있습니다.

### 셀 배치와 범위

- 기본 배치: A=아이템명, B=강화, C=아이템명, D=강화 …
- 범위를 B2:M56으로 지정하면 B열을 첫 아이템명, C열을 첫 강화수치로 봅니다.
- 각 셀에 `초심자의 권갑 +9`처럼 들어 있다면 **각 셀에 아이템명** 배치를 선택합니다.
- 범위를 비우면 시트 전체를 처리합니다. 제목·머리글·설명은 자동 삭제하지 않으므로 범위로 제외하세요.
- 붙여넣은 표의 시작 주소는 A1로 취급합니다. 파일 선택은 원본 엑셀 주소를 사용합니다.
- 숨김 행·열도 선택 범위에 포함되면 처리합니다. 병합 셀은 실제 값이 있는 시작 셀만 읽습니다.
- 여러 시트를 합쳐 출력하지 않으며, 한 시트씩 선택해 변환합니다.

### 적용 규칙

- 무기 11종, 방어구 15종, 망토 4종, 장신구 5종을 지원하며 사용자 확정 규칙에 따라 등록된 이름 코드를 모든 장비에 공통 적용합니다. 전체 매핑은 `src/items/rules.js`, 방어구 검증 기록과 장신구·망토 규칙은 [ARMOR_RULES.md](ARMOR_RULES.md)에 있습니다.
- 망토 코드는 전투 망토 1216, 파괴 망토 1226, 정령 망토 1236, 용맹 망토 1246입니다. 기존 이름 코드 5자리를 동일하게 붙입니다.
- 장신구 코드는 목걸이 1301, 귀걸이 1302, 팔찌 1303, 반지 1304, 허리띠 1305입니다. 1225의 명칭은 장화입니다.
- 장비 코드 4자리 + 접두/이름 코드 5자리로 구성한 9자리 코드입니다.
- 위에서 아래, 각 행의 왼쪽에서 오른쪽 순서로 처리하고 중복을 유지합니다.
- 첫 행도 데이터로 처리합니다. 입력된 Markdown 표의 구분선만 제외하며 첫 줄 데이터는 삭제하지 않습니다.
- 빈 아이템 쌍은 건너뛰지만, 이름 없이 강화수치만 있는 쌍은 오류로 표시합니다.
- 강화 없음=0. 이름 뒤 `+9` 또는 ` 9`를 읽으며, 별도 강화 셀 값이 있으면 해당 값을 우선합니다.
- 서로 다른 강화수치가 이름과 별도 셀에 있으면 별도 셀 사용 사실을 표시합니다.
- 강화수치는 0 이상의 정수입니다. `+`와 숫자의 선행 0은 제거하여 정수로 출력합니다.
- `그을린의→그을린`, `경속의→결속의`, `초심자→초심자의`, `숙련자→숙련자의`를 보정합니다.
- `전투방패→전투 방패` 및 규칙표와 일치하는 띄어쓰기 차이도 보정합니다.
- 그 밖의 불명확한 오타는 추측하지 않고 오류로 표시합니다. `진시르이=55302`는 최종 규칙표 그대로입니다.
- 접두/이름 또는 장비 종류를 확인할 수 없으면 임의의 코드를 생성하지 않습니다.

### 결과

- 원본 셀 위치, 입력 아이템, 코드, 강화수치, 보정 내역, 오류 이유를 확인합니다.
- 머리글 없는 2열 TSV로 복사하거나 다운로드합니다.
- 오류가 있으면 기본 출력은 비워 두며, **오류 항목을 제외하고 정상 항목만 출력**을 선택해야 부분 결과를 복사할 수 있습니다.
- 결과에서 오류만/보정 항목만 필터링해도 TSV의 순서와 대상은 바뀌지 않습니다.
- 복사 후 엑셀의 시작 셀에서 Ctrl+V를 누르면 두 열로 들어갑니다.
- 사내 HTTP 접속 등에서 자동 복사가 제한되면 결과창에서 Ctrl+C 또는 TSV 저장을 사용합니다.

### 지원 범위

- 아이템 변환 입력 파일: 최대 25MB, 시트당 값/수식이 있는 셀 최대 200,000개.
- XLSX 압축 내부의 개별 구성 파일은 32MB, 전체 해제 크기는 128MB 이내입니다. ZIP64는 지원하지 않습니다.
- 브라우저의 deflate-raw 압축 해제 기능을 사용합니다. 최신 Chrome/Edge를 권장합니다.
- 엑셀 수식은 실행하지 않고 저장된 계산 결과를 사용합니다. 저장된 결과가 없거나 셀 오류가 있으면 오류로 표시합니다.
- 텍스트 파일은 UTF-8로 읽습니다. 인코딩 오류는 파일을 다시 저장하거나 셀 붙여넣기로 처리하세요.

### 3. 아이템 지급 매크로

변환 결과에서 **매크로 Python 다운로드**를 누르면 코드와 강화도를 각각 `a`, `b`에 넣은 `.py` 파일을 생성합니다.

다운로드한 파일을 Windows에서 실행하면 준비 안내와 실행 GUI가 열립니다.
**전체 실행** 또는 **절반 실행 후 대기 → 나머지 실행**을 선택할 수 있으며, 진행 기록을 저장해 이어서 실행할 수 있습니다.

브라우저는 게임을 직접 조작하지 않습니다. 게임 조작은 다운로드한 Python 파일을 실행한 PC에서 수행합니다.

아이템 변환 후 결과창 옆의 **매크로 Python 다운로드**를 누릅니다.
표시된 정상 결과의 코드와 강화수치를 각각 `a`, `b`에 포함한 `.py` 파일을 브라우저에서 만듭니다.
데이터나 생성된 파일을 서버에 업로드하지 않으며 EXE 빌드 과정이 없습니다.
오류가 있으면 기존과 동일하게 **정상 항목만 출력**에 동의해야 다운로드할 수 있습니다.
변환 내역 필터는 매크로에 포함할 대상을 바꾸지 않습니다.

### 실행 PC 준비 (최초 한 번)

- Windows용 Python 3.9 이상과 tkinter가 필요합니다. 일반적인 python.org Windows 설치에 tkinter가 포함됩니다.
- 기존 매크로를 실행하던 동일한 Python 환경을 사용할 수 있습니다.
- PowerShell에서 설치합니다. `py`를 사용할 수 없으면 설치한 Python의 `python` 명령으로 바꾸세요.

```powershell
py -m pip install pyautogui pydirectinput keyboard
```

### 실행 방법

1. 다운로드한 `ItemCollection_날짜.py`를 Python으로 실행합니다. IDLE에서 열어 F5로 실행해도 됩니다.
2. 일반 권한이면 별도 Python 프로세스로 관리자 실행을 요청합니다. Windows 관리자 승인 창에서 허용하세요.
3. 승인 취소 또는 회사 정책으로 권한이 허용되지 않으면 입력을 실행하지 않습니다.
4. GUI에 **전체 화면, 로비 화면에서 채팅을 켜둔 상태에서 실행** 안내가 표시됩니다.
5. 기본 모니터를 **1920 × 1080**, 게임을 전체 화면으로 맞추고 채팅 입력란을 비웁니다. 다른 UI 배치에 맞춰 좌표를 자동 탐지하지 않습니다.
6. **1. 전체 구간 실행** 또는 **2. 절반 실행 후 대기**를 선택합니다. 준비 확인 체크박스 없이 실행할 수 있습니다.
7. **실행**을 누르면 GUI가 최소화됩니다. **5초 안에 게임 창을 선택**하세요. 카운트다운 끝에 활성화된 창을 입력 대상으로 사용합니다.
8. 절반 모드에서는 앞 절반만 실행하고 GUI로 돌아옵니다. 게임을 다시 준비한 뒤 **나머지 실행**을 누릅니다. 홀수일 때 앞 절반에 한 개 더 포함합니다.
9. **F8** 또는 마우스를 화면 왼쪽 위 모서리로 이동해 중지할 수 있습니다. 게임에서 다른 창으로 전환되어도 다음 입력 전에 중지합니다.

파일이 편집기로 열리면 PowerShell에서 파일 경로를 지정해 실행하세요.


### 4. 드랍 테이블 검수

#### 담당자: 공통 데이터 등록

1. **서버 PC**에서 [http://localhost:5175/](http://localhost:5175/)에 접속합니다.
2. **드랍 테이블 검수 → 담당자 데이터 등록 / 갱신**을 펼칩니다.
3. **Drop · NPC · Item · String** 파일 4개를 선택해 등록합니다.
4. 분석이 완료되면 직원들이 같은 데이터를 조회할 수 있습니다.

각 파일은 **XLSB / XLSX**, 최대 **160MB**를 지원합니다. 등록은 서버 PC의 로컬 접속으로 제한하며, 별도 계정·로그인 관리 기능은 없습니다.

Git 저장소에서는 `data/`를 제외하므로 **새로 내려받은 프로젝트에는 공통 데이터가 없을 수 있습니다.** 이 경우 최초 등록이 필요합니다. 배포본에 `data/drop-seed.json`이 있으면 현재 등록 데이터가 없을 때 초기 자료로 사용합니다.

#### 사용자: 몬스터 드랍 조회

몬스터 이름 또는 ID를 검색하면 **아이템명 · 인게임 ID · 수량 · 최종 확률**을 확인할 수 있습니다.

- `Drop_Info → Drop_Group → Drop_Item`을 연결하고 NPC·Item·String에서 이름과 분류를 찾습니다.
- 아이템명을 찾지 못하면 ID를 그대로 표시합니다.
- 같은 ID가 중복되면 `VERSION`의 **v 뒤 숫자가 가장 큰 행**을 사용합니다. 동일 최신 버전의 값이 충돌하면 진단 정보를 표시합니다.
- NPC 미연결 드랍 ID는 검색 결과 최하단에 배치합니다.
- 같은 그룹은 같은 계열의 배경색으로 구분합니다.
- 그룹 확률·그룹 내 확률·ID·검수·원본 경로 등은 기본적으로 접어 두고 필요할 때 펼칩니다.
- 등록 자료를 갱신한 뒤에는 **공유 데이터 새로고침**으로 새 데이터를 불러옵니다.

상세 연결 규칙과 계산 기준은 [DROP_GUIDE.md](DROP_GUIDE.md)를 참고하세요.

### 5. 드랍 변경 비교

1. 드랍 검수에 공통 기준 자료가 등록되어 있는지 확인합니다.
2. 서버 PC의 **드랍 변경 비교**에서 이전·변경 Drop 파일 2개를 선택합니다.
3. **두 파일 비교**를 실행합니다.
4. 변경 몬스터 목록과 카테고리별 요약을 확인하고, 몬스터를 선택해 상세 변경을 봅니다.

각 Drop 파일은 **XLSB / XLSX**, 최대 **160MB**를 지원합니다.
비교 시작 시 등록된 **NPC · Item · String**을 양쪽에 동일하게 적용합니다. 기준 자료를 나중에 갱신해도 저장된 비교 결과는 자동으로 바뀌지 않으며, 새 기준을 적용하려면 다시 비교해야 합니다.

- 아이템 추가·제거, 확률 증감, 지급 수량과 추첨 구성 변경을 구분합니다.
- `(Temp)NPC_Info`의 고유번호·NPC 구분·배치 맵·사냥터·표시 레벨을 활용해 몬스터를 분류합니다.
- 요약에서는 개별 아이템 이름과 확률을 나열하지 않고 **해당 몬스터들의 드랍이 어떻게 바뀌었는지** 설명합니다.
- 상승과 하락이 섞여 있으면 각각 요약하고, 전체 몬스터와 일부 몬스터의 변경을 구분합니다.
- 변경 아이템의 등급이 모두 같을 때만 등급을 언급합니다.
- 그룹 정보는 기본적으로 접혀 있으며, 몬스터 상세에서 이전·변경 확률과 수량을 확인할 수 있습니다.
- **전체 요약 TXT**와 **선택한 몬스터의 상세 TSV**를 저장할 수 있습니다.

상세 비교 기준은 [DROP_COMPARE_GUIDE.md](DROP_COMPARE_GUIDE.md)를 참고하세요.

## 확률과 숫자 표시

| 항목 | 표시 기준 |
| --- | --- |
| 확률·확률 차이 | 최대 소수 4자리, 5번째 자리에서 반올림 |
| 확률 차이 단위 | %p. 예: 10% → 15%는 +5%p |
| 실제 확률 차이가 없는 경우 | 차이 없음 |
| 실제 차이가 있지만 표시상 0으로 반올림되는 경우 | 0 %p (반올림) |
| 평균 필요 처치 수 | 처치당 기대 당첨 횟수의 역수를 반올림 |
| 반올림한 평균 필요 처치 수가 같은 경우 | 차이 없음 |
| 최소·최대 수량이 같은 경우 | 1~1 대신 1 |
| 계산할 수 없는 경우 | 계산 불가 등 별도 상태로 표시 |

**평균 필요 처치 수**는 `1 ÷ 처치당 기대 당첨 횟수`입니다. 예를 들어 0.05이면 20마리입니다.
1 미만은 **1마리 미만**, 기대 당첨 횟수가 0이면 **획득 불가**로 표시합니다.
장기간 당첨 횟수를 기준으로 환산한 값으로, 첫 획득까지의 대기 시간이나 획득 보장 횟수를 의미하지 않습니다.

반올림은 화면과 내보내기 표시값에 적용하며, 내부 비교 정밀도와 원본 JSON·ID·아이템 코드는 유지합니다.
드랍 계산은 테이블과 구현된 추첨 가정을 기준으로 하며, 게임의 이벤트·버프·서버 보정을 자동으로 반영하지 않습니다.

| 공유 드랍 자료 | 서버의 `data/drop-current.json` | 브라우저·서버 종료 후에도 유지 |

JSON 비교와 아이템 변환의 원본은 서버에 업로드하지 않습니다.
드랍 자료는 서버에서 분석하며, 분석용 원본 업로드 파일은 작업 종료 시 정리합니다. 등록·비교 실패 시 기존에 저장된 결과를 유지합니다.

`data/`는 `.gitignore`에 포함되어 있어 새 업무 데이터가 기본적으로 커밋 대상에서 제외됩니다. 이미 Git이 추적 중인 파일에는 이 제외 규칙이 소급 적용되지 않습니다.

## 테스트

프로젝트 최상위에서 Node.js 테스트를 실행합니다.

```powershell
npm test
```

JSON 구조 비교, 아이템 변환·엑셀 읽기, 매크로 생성, 드랍 연결·버전·확률·비교·요약·표시 및 테마 상태 처리를 검증합니다.

Python 매크로의 분할·진행 저장·이어하기 테스트는 다음 명령으로 실행합니다. 이 테스트는 게임이나 마우스를 조작하지 않습니다.

```powershell
py -m unittest discover -s tests -p "test_macro.py" -v
```

업데이트 전에 다운로드한 Python 파일은 자동으로 갱신되지 않습니다. 사이트를 새로고침하고 변환 결과에서 **매크로 Python 다운로드**를 다시 눌러 새 파일을 실행하세요.

자동 테스트와 실제 게임 입력 검증은 별개입니다. Windows 관리자 승인, 게임 화면 배치와 입력 결과는 매크로 실행 환경에서 확인해야 합니다.
