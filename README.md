# QA 통합 툴 1.4.5

게임 QA용 브라우저 도구입니다. 홈에서 JSON 폴더 비교, 아이템 코드 변환, 드랍 테이블 검수, 드랍 변경 비교를 선택합니다.
JSON 비교와 아이템 변환은 브라우저에서 처리하며 원본을 수정하지 않습니다. 드랍 테이블은 담당자가 서버에 등록한 자료를 공유합니다. 웹사이트는 외부 CDN 및 추가 패키지 설치가 필요하지 않습니다. 다운로드한 매크로는 Windows의 Python과 별도 패키지가 필요합니다.
메뉴를 이동해도 결과를 유지합니다. JSON 비교와 아이템 변환 입력은 새로고침 시 초기화되며, 공유 드랍 데이터는 서버에 저장되어 유지됩니다.

## 1.4.3 화면 정리

- 드랍 검수: NPC 미연결 드랍 ID는 검색 결과 마지막에 정렬, 같은 그룹은 같은 파스텔 배경색.
- 기본 열은 아이템명·인게임 ID·수량·최종 확률. 계산 근거 열은 접힌 상태이며 펼쳐서 확인합니다.
- 몬스터 부가 정보는 ID·레벨과 Drop 시트·행으로 간소화합니다.
- 평균 필요 처치 수는 기존 처치당 기대 당첨 횟수의 역수를 반올림합니다. 0.05는 20마리입니다. 1 미만은 '1마리 미만', 확률 0은 '획득 불가', 계산 불가는 별도 표시합니다.
- 변경 비교: 그룹 카드 기본 접기, 이전 확률 / 변경 확률로 명칭 통일, 동일 최소·최대 수량은 한 숫자로 표시.
- 상승은 옅은 빨강, 하락은 옅은 파랑으로 아이템 영역과 요약 문장을 표시합니다.

## 기존 프로젝트에 적용

1. VS Code에서 현재 서버를 실행 중인 터미널을 클릭하고 Ctrl+C로 종료합니다.
2. 이 압축파일을 해제하고, 안의 파일과 폴더를 **기존 json-folder-compare 프로젝트 최상위에 복사해 덮어씁니다.**
3. 프로젝트 안에 qa-tools-update 폴더를 새로 넣는 방식이 아닙니다. 기존 index.html 자리에 새 index.html이 와야 합니다.
4. 특히 **server.mjs와 server / src / data 폴더를 함께 복사**하세요. 새 메뉴에서 사용하는 파일 경로가 서버에 추가되었습니다.
5. 기존 .git 폴더는 그대로 유지합니다. 이 패키지에는 .git과 node_modules가 없습니다.
6. 프로젝트 터미널에서 아래 명령을 실행합니다.

```powershell
node server.mjs --port 5175
```

7. http://localhost:5175/ 에서 Ctrl+F5를 누릅니다.
8. 상단에 **QA 통합 툴**, 메뉴에 **홈 / JSON 폴더 비교 / 아이템 코드 변환 / 드랍 테이블 검수 / 드랍 변경 비교**이 보이는지 확인합니다.

이전 서버를 종료하지 않고 새 서버를 추가로 켜면 포트 사용 중 오류가 발생합니다.
5175가 다른 프로그램에 의해 사용 중이면 프로세스를 확인해야 합니다. 관련 없는 프로세스를 일괄 종료하지 마세요.
드랍 테이블 기능은 새 Node 서버의 API가 필요합니다. 위의 node server.mjs 명령으로 실행하세요.

## 독립 실행 / 사내 접속

- Node.js를 설치한 PC에서 `start.bat` 또는 `npm run dev`로 실행합니다.
- 기본 로컬 주소는 http://localhost:5175/ 입니다. 실행 창을 켜둡니다.
- 사내 공유는 `share-lan.bat` 또는 `npm run share`로 실행하고 Network 주소를 공유합니다.
- 호스트 PC 전원과 해당 포트의 네트워크 접근이 유지되어야 합니다. 웹 도구 사용에는 브라우저만 필요합니다. 매크로 실행 PC에는 Python과 매크로 패키지를 설치해야 합니다.
- 이 업데이트에는 Windows 부팅 시 자동 실행 / 서비스 등록은 포함하지 않았습니다.

## 드랍 변경 비교 (1.4.3)

**드랍 변경 비교**에서 담당자가 구버전·신버전 Drop 파일 두 개를 등록합니다. 현재 등록된 최신 NPC·Item·String이 양쪽에 동일하게 적용됩니다.

- 변경된 몬스터 목록 → 지역·고유번호·레벨·아이템 등급별 요약 → 몬스터 선택 시 상세 변경.
- 확률 변화, 아이템 추가·제거, 지급 수량과 추첨 구성 변경을 구분합니다.
- 요약 TXT와 개별 상세 TSV 저장, 서버 재시작 후 결과 유지.
- 기존 공유 드랍 조회 데이터는 교체하지 않습니다. 새 비교 결과가 이전 비교 결과를 대체합니다.
- 자세한 사용법과 검증 결과는 **DROP_COMPARE_GUIDE.md**를 참고하세요.

## 드랍 테이블 검수 (1.3)

**드랍 테이블 검수** 메뉴에서 몬스터 이름 또는 ID를 입력하세요. 첨부된 최신 Drop/NPC/String과 기존 Item 파일로 만든 초기 데이터를 포함하므로 바로 조회할 수 있습니다.

- 담당자가 서버 PC의 `http://localhost:5175/`에서 Drop, NPC, Item, String 파일 4개를 등록합니다.
- 직원들은 내부 IP 주소로 접속해 같은 자료를 조회합니다. 매번 업로드할 필요가 없습니다.
- `.xlsb`와 `.xlsx`를 지원하며, 같은 ID는 숫자상 최신 VERSION을 사용합니다.
- 단계별 확률, 최종 경로 확률, 아이템 한글 이름, 원본 시트·행·버전을 표시합니다. 이름이 없으면 ID를 표시합니다.
- 서버를 다시 켜도 등록 데이터가 유지되며, 갱신에 실패하면 이전 데이터가 유지됩니다.
- 상세 계산 규칙, 등록 방법, 버전 처리와 저장 위치는 **DROP_GUIDE.md**를 참고하세요.

## 아이템 코드 변환

### 입력 방법

- **셀 붙여넣기**: 엑셀에서 데이터 범위를 복사해 입력창에 붙여넣습니다.
- **엑셀 파일**: .xlsx 파일을 선택하고 처리할 시트를 고릅니다.
- UTF-8 .csv(쉼표 구분), .tsv, .txt(탭 구분)도 읽습니다.
- .xls/.xlsm 또는 암호화된 파일은 .xlsx로 저장하거나 셀을 복사해 붙여넣으세요.
- **제공 예시 불러오기**로 사용자 표 56행 전체를 확인할 수 있습니다.

### 셀 배치와 범위

- 기본 배치: A=아이템명, B=강화, C=아이템명, D=강화 …
- 범위를 B2:M56으로 지정하면 B열을 첫 아이템명, C열을 첫 강화수치로 봅니다.
- 각 셀에 `초심자의 권갑 +9`처럼 들어 있다면 **각 셀에 아이템명** 배치를 선택합니다.
- 범위를 비우면 시트 전체를 처리합니다. 제목·머리글·설명은 자동 삭제하지 않으므로 범위로 제외하세요.
- 붙여넣은 표의 시작 주소는 A1로 취급합니다. 파일 선택은 원본 엑셀 주소를 사용합니다.
- 숨김 행·열도 선택 범위에 포함되면 처리합니다. 병합 셀은 실제 값이 있는 시작 셀만 읽습니다.
- 여러 시트를 합쳐 출력하지 않으며, 한 시트씩 선택해 변환합니다.

### 적용 규칙

- 사용자 최종 규칙표만 사용합니다. 전체 매핑은 `src/items/rules.js`에 있습니다.
- 무기 코드 4자리 + 접두/이름 코드 5자리로 구성한 9자리 코드입니다.
- 위에서 아래, 각 행의 왼쪽에서 오른쪽 순서로 처리하고 중복을 유지합니다.
- 첫 행도 데이터로 처리합니다. 입력된 Markdown 표의 구분선만 제외하며 첫 줄 데이터는 삭제하지 않습니다.
- 빈 아이템 쌍은 건너뛰지만, 이름 없이 강화수치만 있는 쌍은 오류로 표시합니다.
- 강화 없음=0. 이름 뒤 `+9` 또는 ` 9`를 읽으며, 별도 강화 셀 값이 있으면 해당 값을 우선합니다.
- 서로 다른 강화수치가 이름과 별도 셀에 있으면 별도 셀 사용 사실을 표시합니다.
- 강화수치는 0 이상의 정수입니다. `+`와 숫자의 선행 0은 제거하여 정수로 출력합니다.
- `그을린의→그을린`, `경속의→결속의`, `초심자→초심자의`, `숙련자→숙련자의`를 보정합니다.
- `전투방패→전투 방패` 및 규칙표와 일치하는 띄어쓰기 차이도 보정합니다.
- 그 밖의 불명확한 오타는 추측하지 않고 오류로 표시합니다. `진시르이=55302`는 최종 규칙표 그대로입니다.
- 접두/이름 또는 무기를 확인할 수 없으면 임의의 코드를 생성하지 않습니다.

### 결과

- 원본 셀 위치, 입력 아이템, 코드, 강화수치, 보정 내역, 오류 이유를 확인합니다.
- 머리글 없는 2열 TSV로 복사하거나 다운로드합니다.
- 오류가 있으면 기본 출력은 비워 두며, **오류 항목을 제외하고 정상 항목만 출력**을 선택해야 부분 결과를 복사할 수 있습니다.
- 결과에서 오류만/보정 항목만 필터링해도 TSV의 순서와 대상은 바뀌지 않습니다.
- 복사 후 엑셀의 시작 셀에서 Ctrl+V를 누르면 두 열로 들어갑니다.
- 사내 HTTP 접속 등에서 자동 복사가 제한되면 결과창에서 Ctrl+C 또는 TSV 저장을 사용합니다.

### 지원 범위

- 아이템 변환 입력 파일: 최대 25MB, 시트당 값/수식이 있는 셀 최대 200,000개.
- XLSX 압축 내부의 개별 구성 파일은 32MB, 전체 해제 크기는 128MB 이내입니다. ZIP64는 지원하지 않습니다.
- 브라우저의 deflate-raw 압축 해제 기능을 사용합니다. 최신 Chrome/Edge를 권장합니다.
- 엑셀 수식은 실행하지 않고 저장된 계산 결과를 사용합니다. 저장된 결과가 없거나 셀 오류가 있으면 오류로 표시합니다.
- 텍스트 파일은 UTF-8로 읽습니다. 인코딩 오류는 파일을 다시 저장하거나 셀 붙여넣기로 처리하세요.

## 매크로 Python 다운로드 (1.2)

아이템 변환 후 결과창 옆의 **매크로 Python 다운로드**를 누릅니다.
표시된 정상 결과의 코드와 강화수치를 각각 `a`, `b`에 포함한 `.py` 파일을 브라우저에서 만듭니다.
데이터나 생성된 파일을 서버에 업로드하지 않으며 EXE 빌드 과정이 없습니다.
오류가 있으면 기존과 동일하게 **정상 항목만 출력**에 동의해야 다운로드할 수 있습니다.
변환 내역 필터는 매크로에 포함할 대상을 바꾸지 않습니다.

### 실행 PC 준비 (최초 한 번)

- Windows용 Python 3.9 이상과 tkinter가 필요합니다. 일반적인 python.org Windows 설치에 tkinter가 포함됩니다.
- 기존 매크로를 실행하던 동일한 Python 환경을 사용할 수 있습니다.
- PowerShell에서 설치합니다. `py`를 사용할 수 없으면 설치한 Python의 `python` 명령으로 바꾸세요.

```powershell
py -m pip install pyautogui pydirectinput keyboard
```

### 실행 방법

1. 다운로드한 `ItemCollection_날짜.py`를 Python으로 실행합니다. IDLE에서 열어 F5로 실행해도 됩니다.
2. 일반 권한이면 별도 Python 프로세스로 관리자 실행을 요청합니다. Windows 관리자 승인 창에서 허용하세요.
3. 승인 취소 또는 회사 정책으로 권한이 허용되지 않으면 입력을 실행하지 않습니다.
4. GUI에 **전체 화면, 로비 화면에서 채팅을 켜둔 상태에서 실행** 안내가 표시됩니다.
5. 기본 모니터를 **1920 × 1080**, 게임을 전체 화면으로 맞추고 채팅 입력란을 비웁니다. 다른 UI 배치에 맞춰 좌표를 자동 탐지하지 않습니다.
6. 준비 확인에 체크하고 **1. 전체 구간 실행** 또는 **2. 절반 실행 후 대기**를 선택합니다.
7. **실행**을 누르면 GUI가 최소화됩니다. **5초 안에 게임 창을 선택**하세요. 카운트다운 끝에 활성화된 창을 입력 대상으로 사용합니다.
8. 절반 모드에서는 앞 절반만 실행하고 GUI로 돌아옵니다. 게임을 다시 준비하고 체크한 뒤 **나머지 실행**을 누릅니다. 홀수일 때 앞 절반에 한 개 더 포함합니다.
9. **F8** 또는 마우스를 화면 왼쪽 위 모서리로 이동해 중지할 수 있습니다. 게임에서 다른 창으로 전환되어도 다음 입력 전에 중지합니다.

파일이 편집기로 열리면 PowerShell에서 파일 경로를 지정해 실행하세요.

```powershell
py "C:\Users\사용자명\Downloads\ItemCollection_날짜.py"
```

Python 패키지가 다른 인터프리터에 설치됐다면 실행 오류 창의 **현재 Python** 경로를 확인하세요.
필요한 경우 해당 경로로 `-m pip install pyautogui pydirectinput keyboard`를 실행합니다.

### 이어하기와 중복 처리

- 전체 데이터의 코드·강화·순서를 기준으로 진행을 `%LOCALAPPDATA%\QATools\ItemMacro`에 저장합니다.
- 창을 닫았다 다시 열어도 이어갑니다. 같은 데이터를 다시 다운로드하면 기존 진행 기록을 사용합니다.
- 새로운 캐릭터 등에서 같은 목록을 처음부터 실행하려면 **진행 초기화**를 누르세요. 이미 지급된 아이템을 회수하는 기능은 아닙니다.
- 중복 항목은 별개 항목으로 실행합니다. 완료된 항목을 정상 이어하기에서 다시 입력하지 않습니다.
- 입력 도중 중단된 항목은 지급 여부를 알 수 없어 자동 재전송하지 않습니다. GUI에서 해당 아이템의 **재시도 / 건너뛰기 / 취소**를 선택합니다.
- 재시도 전에 게임에서 실제 지급 여부를 확인하고, 채팅창에 남은 글자를 지우세요. 이미 지급된 항목을 재시도하면 중복 지급될 수 있습니다.
- 진행률은 입력 전송 기준입니다. 이 코드에는 게임의 성공 응답이나 인벤토리를 읽는 기능이 없습니다.
- 같은 Windows 세션에서 매크로 창을 여러 개 실행하지 않도록 처리했습니다.

### 원본 매크로와의 관계

- 원본의 `@item 코드 1`, `@itemEnchant 코드 1 강화` 명령을 유지했습니다.
- 원본 준비 좌표 `(960, 570)`, 입력 좌표 `(300, 1050)`, 전송 좌표 `(700, 1050)`를 유지했습니다.
- 고정 구간 420/700 대신 실제 아이템 개수로 전체/절반 범위를 계산합니다.
- 빈 마지막 행 때문에 코드 개수가 늘어나던 문제를 제거했습니다.
- 브라우저는 매크로를 실행하지 않습니다. 다운로드한 파일을 실행한 PC의 게임에 입력합니다.
- `src/items/macro-template.py`는 사이트용 템플릿입니다. 직접 실행하지 말고 사이트에서 데이터가 포함된 파일을 다운로드하세요.

## 검증

```powershell
npm test
```

- Node 자동 테스트 62개 통과: 기존 JSON 비교, 변환 규칙, 순서/중복, 보정/오류, 범위, TSV/CSV 및 XLSX 읽기, 드랍 연결/버전/확률과 공유 데이터 API.
- 사용자 검증 예시 7개 및 코드 생성 예시 2개 확인.
- 제공된 전체 표: 56행, 240건. 정상 238건, 오류 2건, 보정 24건.
- 미등록 오류는 `카말리아의 심장`, `카말리아의 날개`뿐입니다. 첫 두 건은 모두 `112220101` + `0`으로 보존됩니다.
- 동일 데이터를 담은 테스트 XLSX를 읽었을 때 붙여넣기 경로와 동일한 TSV 출력 확인.
- 정적 파일과 드랍 API 응답 확인. 비공개 파일 경로는 404이며, 드랍 등록 API 외 일반 경로의 POST는 405입니다.
- 드랍 기능은 실제 첨부 4개 파일로 HTTP 업로드부터 재시작 후 유지까지 검증했습니다. 실제 브라우저 화면/클립보드/파일 선택의 종단 간 검증은 이 환경에서 수행하지 못했습니다.

Python 분할/이어하기 테스트 (게임이나 마우스를 조작하지 않음):

```powershell
py -m unittest discover -s tests -p "test_macro.py" -v
```

- Python 테스트 17개 통과: 전체/홀수/짝수 분할, 재실행, 중단된 항목의 재시도/건너뛰기, 잘못된 진행 기록, 저장 실패.
- 생성된 Python의 구문 검사와 데이터 재해석 결과가 원본 변환 TSV와 일치하는지 확인했습니다.
- Windows 관리자 승인, GUI 표시, 긴급 중지 키와 실제 게임 지급은 이 환경에서 실행 검증하지 못했습니다. 먼저 소수의 항목으로 확인하세요.
